# Learning design brief

Audience: an interested technical learner who can read Python lists, calls and a
short loop. No statistics prerequisite. This is a 30-investigation core route,
about 192 minutes for initial activities, plus exploration and a final project.
The timing is an author estimate, not an observed completion-time claim.

Each investigation targets one observable action. Source-of-truth objectives,
prerequisites in sequence, data provenance, prompts, feedback and local limits are
in `src/course.json`. Python examples are in `python/`.

| Module | Observable outcome | Preparation | Misconception exposed by the fresh task |
| --- | --- | --- | --- |
| Ask a better question | Specify a falsifiable comparison with a meaningful boundary | Reading Python and basic arithmetic | A broad positive slogan or one agreeing observation proves a mechanism |
| Design a fair test | Identify assignment units, compare within blocks, recognise interactions | Outcomes, variables, measurement | More readings always mean more independent experiments; one average fits every setting |
| Read the observations | Diagnose distribution shape, selection, drift and missingness | Experimental conditions and units | A precise or attractive summary guarantees representative stable evidence |
| Put uncertainty to work | Interpret intervals and compare their target with a useful threshold | Mean, spread, independent units | An interval covers individuals; resampling fixes bias; nonzero means useful |
| Challenge your conclusion | Explain the null model and how searching/stopping change inference | Repeated sampling and effect size | p is probability the null is true; threshold chasing is a one-test procedure |
| Make the evidence travel | Collect, scope and export a reproducible conditional finding | Entire core route | Correlation identifies cause; a rerun is a new-data replication; uploading validates design |

These misconceptions are author hypotheses, not observed novice responses.

## Route and feedback

A small complete example is visible in every editor, with labelled inputs.
Prediction is optional and stored separately from output. Run executes the source;
worked output is generated by the same source at build time, never typed as a
measurement. A change-one-thing task develops the mechanism. A new context then
requires a decision, with two progressive hints and feedback after submission.
Correct answers do not gate reading or claim mastery. The essential definitions
and interpretation remain visible with optional disclosures closed.

The investigation moves from invented inputs to seeded simulations with known
truth, then real local measurements, then learner-provided evidence. Lessons 29
and 30 deliberately state that repeated blocks in a single runtime are not
independent sessions. A CSV's syntax does not establish its scientific validity.

## Depth and deferred subjects

The core includes confounding, instrument bias, controls, randomisation, blocking,
pseudoreplication, factorial interaction, missingness, interval coverage,
bootstrap assumptions, paired log ratios, power simulation, null models, exact
paired randomisation, multiplicity, optional stopping, residuals, causal
alternatives, replication and an evidence report.

Bayesian inference, advanced missing-data methods, valid sequential procedures,
hierarchical models and survival analysis are explicit further study. Adding
those to existing pages would overwhelm the single-outcome lesson structure.

## Evaluation plan

Check execution against NumPy/SciPy reference behaviour, inspect all pages at
phone and desktop widths, inspect both themes, and exercise feedback, loading,
error, Stop/restart, persistence and export paths. These are implementation
checks, not evidence of learning. A next formative study should observe a novice
without coaching, then ask for a fresh experimental-unit and interval task;
record first attempts, assistance and post-help reasoning separately.
